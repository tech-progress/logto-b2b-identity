# Finite default-path advisory review

**Pre-freeze review snapshot — 2026-10-06:** Recipe **1.0.2** was not released when this review was recorded against the [original inputs](artifact-review/inputs/) and exact cached image digests in [ARTIFACT_REVIEW.md](ARTIFACT_REVIEW.md). The public **1.0.1** source then was [tech-progress/logto-b2b-identity at 9d468c9](https://github.com/tech-progress/logto-b2b-identity/tree/9d468c9c8bddbb0b3ef01a4fcd236dbf6f5f0554). These are historical observations, not current release-channel assertions. Logto remains 1.44.0, PostgreSQL 17.11 and both cached Node environments 22.23.3. No pin, image, infrastructure or runtime change was made by this review. See [PUBLISHING.md](PUBLISHING.md) for the source selection and qualification boundary.

This is a bounded assessment of published first-party advisories and their default request triggers, not a vulnerability scanner report or security certification. [advisory-records.json](artifact-review/advisory-records.json) preserves reviewed advisory identifiers, ranges and first-party links; [provenance.json](artifact-review/provenance.json) records exact response hashes and input hashes. Empty advisory endpoints are not evidence that a component has no vulnerabilities.

## Optional outbound and commercial triggers

The cached image injects an OSS survey endpoint. Tagged [console submission code](https://github.com/logto-io/logto/blob/79e9e3b0d9f505260d09c80d8a015e56fbc0ec01/packages/console/src/pages/OssOnboarding/submit-oss-onboarding.ts) requires `isDevFeaturesEnabled`, a valid endpoint and an onboarding survey payload. Tagged [console environment logic](https://github.com/logto-io/logto/blob/79e9e3b0d9f505260d09c80d8a015e56fbc0ec01/packages/console/src/consts/env.ts) permits development features via build environment or a console localStorage setting. The original recipe does not set `DEV_FEATURES_ENABLED`; users can change the localStorage trigger. This is a conditional onboarding egress path, not proof of automatic default reporting or a network test. Compiled console settings must be considered if the parent changes this behavior.

Backend [PostHog initialization](https://github.com/logto-io/logto/blob/79e9e3b0d9f505260d09c80d8a015e56fbc0ec01/packages/core/src/utils/posthog.ts) requires a configured public key. [Application Insights initialization](https://github.com/logto-io/logto/blob/79e9e3b0d9f505260d09c80d8a015e56fbc0ec01/packages/app-insights/src/node.ts) requires its connection string. Neither is set in the original recipe or observed image environment. Cloud mode and optional paid/self-hosted functionality are not enabled or licensed by the recipe; consult [LICENSE_REVIEW.md](LICENSE_REVIEW.md) before expanding scope.

## Parent handoff and remaining gates

No concrete default-request vulnerable path requiring an image/pin change was established by this finite advisory review. The Koa range/fix inconsistency and embedded SAML/native assessment limit are explicitly unresolved, and have been reported before proposing changes. No pin change is recommended on this evidence alone. Any parent patch to the frozen recipe, new optional feature or later upstream disclosure requires a targeted update rather than relying on this packet as universal clearance.

Separate local native acceptance passed genuine owner claim, HTTPS login/callback behavior, PKCE code exchange and token validation, B2B memberships/roles/scopes with cross-organization denial, restart, full cold restore and owner recovery. Those runs used private loopback test certificates; all final immutable-source and trusted public Railway repetitions remain pending. Advisory comparisons do not waive them. This review itself started no services, scanned no live endpoints and created no owner, key or cloud project. Zero compute and standard scoped deletion may be demonstrated with honest retention evidence; physical erasure and billing-zero claims are not established here.
